# Production booking venue view — 16 November 2026

Guest booking and staff booking creation now use the approved realistic venue renderer, backed by their existing authorized resource lists. The Flat option remains available. This is an illustrative arrangement of actual spaces, not a surveyed venue model.

## Behavior

- Guest 3D shows one explicit server-provided start/end interval. Court status, price, duration and waitlist eligibility come from that exact row. The same selection handler serves the flat grid and 3D confirmation button.
- Flat preference survives availability refresh and returning from guest details. Changing sport, date, duration or resource pages invalidates stale choices. Time filters resolve the scene against the currently visible rows and clear an unrelated open waitlist form.
- Staff 3D chooses a space, then loads its existing authorized times. An enabled resource is never presented as available at a particular time without checking. Switching views preserves the chosen space and slot. Lists larger than twelve have explicit scene pagination.
- Canvas taps have equivalent HTML controls. Camera buttons support keyboard and touch, while wheel/touch scrolling belongs to the page. WebGL loading or rendering failure returns to the flat controls.
- Three.js is loaded as a separate browser chunk. Rendering runs only when scene/camera state changes; customer typing does not schedule GPU work. Switching views releases textures, geometry, materials, listeners and context.

## Booking correction

Priority membership eligibility previously used noon during slot search but the actual start instant during booking creation. Memberships beginning or ending during the selected day could therefore expose invalid slots or hide valid ones. Slot search now loads the day's overlapping memberships once and checks the same exact start/expiry interval for every candidate. Three failing-before/fixed-after regressions cover morning, afternoon and noon-crossing memberships.

## Release configuration and dependencies

The default five-minute cron was incompatible with the project's observed Hobby deployment limit. Its exact configuration is preserved in `docs/examples/vercel-scheduled-jobs.json`; activation still requires a compatible scheduler and separate acceptance. It was not replaced with a daily schedule that would miss reminder windows. Booking conflict/expired-hold enforcement remains synchronous in the existing booking services. See `BACKGROUND_JOBS.md`.

Reviewed security updates pin Next.js/ESLint configuration 16.4.6, Better Auth/adapter/core 1.7.7 and Zod 4.6.6. Three.js and its types are pinned at 0.187.0. See `SECURITY.md` for advisory scope and the remaining development-tool findings.
